# Go vs Rust Mobile Backend Benchmark - 2026-05-14

## Scope

- Server: `fedora`
- Method: side-by-side local loopback benchmark on the same server
- Production service: left untouched on `127.0.0.1:8081`
- Rust sidecar: `127.0.0.1:18081`
- Go sidecar: `127.0.0.1:18082`
- State safety: both sidecars used copied `data/` directories under `/tmp`
- Workload: read-only mobile endpoints plus login/session creation against copied state
- Tool: ApacheBench (`ab`)
- Remote raw result root: `/tmp/accord_mobile_bench_20260514_090700`

No backend source code was changed during this benchmark.

## Context

This Go service is the legacy baseline for the primary Rust mobile backend. The
benchmark records the behavior and performance baseline used to validate the
Rust replacement against the same mobile API contract and the same real ERPNext
environment.

## Notes

- No `429` responses were observed.
- No ApacheBench failed requests were observed.
- The Go sidecar logged an ERP auth failure during delivery-note field warmup,
  then started successfully and served all tested endpoints with `200`.
- The benchmark found no Go-side runtime blocker for the tested read-only flows.

## Conclusion

The Go implementation remains the historical behavior baseline. On this
side-by-side read-heavy benchmark, the Rust backend matched successful responses
and showed lower latency on most tested endpoints.
